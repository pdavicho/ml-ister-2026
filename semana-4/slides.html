¿Por qué Accuracy Sola Miente?

Imagina un dataset de detección de fraude: 970 transacciones normales y 30 fraudulentas.

Modelo "trampa"

El modelo predice SIEMPRE "normal", sin aprender nada.

Accuracy = 970/1000 = 97%

¿Es un buen modelo? NO — no detecta ni un fraude.

Modelo inteligente

El modelo detecta correctamente 25 de los 30 fraudes.

Accuracy = 985/1000 = 98.5%

Solo un 1.5% más, pero detecta el 83% de los fraudes.

Accuracy sola oculta si el modelo falla en la clase que más importa. Necesitamos métricas más detalladas.

FN (Falso Negativo) — "El paciente tiene cáncer pero dijimos que no". Muy peligroso.
FP (Falso Positivo) — "Dijimos que hay fraude pero era normal". Costoso pero menos peligroso.

Analogía: Prueba de Diagnóstico Médico

Una prueba médica detecta si un paciente tiene o no una enfermedad. Analicemos los 4 resultados posibles.

✅ Verdadero Positivo (TP)

El paciente TIENE la enfermedad y la prueba dijo "Positivo". Correcto — se trata a tiempo.

✅ Verdadero Negativo (TN)

El paciente NO tiene la enfermedad y la prueba dijo "Negativo". Correcto — no necesita tratamiento.

⚠️ Falso Positivo (FP)

El paciente NO tiene la enfermedad pero la prueba dijo "Positivo". Error — tratamiento innecesario, estrés, costo.

🚨 Falso Negativo (FN)

El paciente SÍ tiene la enfermedad pero la prueba dijo "Negativo". Error crítico — no recibe tratamiento.

En medicina, los FN son más peligrosos que los FP. Esto dicta qué métrica optimizar.

Métricas Derivadas de la Matriz

Accuracy (Exactitud)

Acc = (TP + TN) / (TP + TN + FP + FN)

Porcentaje total de predicciones correctas. Engañosa en clases desbalanceadas.

Precision (Precisión)

Prec = TP / (TP + FP)

De todos los que predije como Positivo, ¿cuántos realmente lo eran? Importa cuando el FP es costoso.

Recall (Sensibilidad)

Rec = TP / (TP + FN)

De todos los Positivos reales, ¿cuántos detecté? Importa cuando el FN es peligroso (médico).

F1-Score

F1 = 2 × (Prec × Rec) / (Prec + Rec)

Media armónica de Precision y Recall. Útil cuando ambas importan y hay desbalanceo.

El F1-Score penaliza fuertemente si alguna de las dos (Precision o Recall) es muy baja.

El Trade-off: Precision vs Recall

No puedes maximizar ambas al mismo tiempo. Aumentar Recall generalmente baja Precision y viceversa.

Umbral bajo (threshold ↓)

El modelo predice "Positivo" más fácilmente.

→ Recall sube (detecta más enfermos)

→ Precision baja (más falsos positivos)

Útil en: detección de enfermedades, fraude bancario.

Umbral alto (threshold ↑)

El modelo solo predice "Positivo" cuando está muy seguro.

→ Precision sube (casi no hay FP)

→ Recall baja (pierde algunos positivos)

Útil en: recomendaciones de productos, spam (no enviar a inbox válido).

La elección del umbral depende del problema. Siempre pregunta: ¿qué error es más costoso — FP o FN?

¿Qué es la Validación Cruzada?

El problema del train/test split simple: el resultado depende de CÓMO dividiste los datos (suerte).

Problema del split simple

Si tienes mala suerte en el split, el test set puede contener solo ejemplos fáciles → accuracy inflada.

O solo ejemplos difíciles → accuracy injustamente baja.

Solución: Cross-Validation

Divide los datos en K partes (folds). Entrena K veces, cada vez usando una parte diferente como test.

→ Todos los ejemplos son usados para test exactamente una vez.

CV da una estimación mucho más confiable del rendimiento real del modelo en datos nuevos.

Curva ROC y AUC

La curva ROC (Receiver Operating Characteristic) mide la calidad del modelo en todos los umbrales posibles.

¿Cómo se construye?

Para cada umbral (de 0 a 1):

· Calcula FPR = FP / (FP + TN)

· Calcula TPR = TP / (TP + FN)

· Dibuja el punto (FPR, TPR)

La curva va de (0,0) a (1,1).

AUC — Área Bajo la Curva

Resumen en un solo número: el área bajo la curva ROC.

AUC = 1.0Perfecto
AUC > 0.9Excelente
AUC 0.8–0.9Bueno
AUC = 0.5Igual que adivinar
La curva ROC y AUC son para clasificación binaria. Para multiclase se usa el enfoque One-vs-Rest.

Overfitting vs Underfitting

El diagnóstico clave: ¿el error en train y en validación están cercanos o muy separados?

Underfitting (alto sesgo)

Train acc: baja

Val acc: baja

El modelo es demasiado simple. Aumenta complejidad (más profundidad, más features).

Buena generalización

Train acc: alta

Val acc: similar a train

El modelo generaliza bien. Esta es la zona objetivo.

Overfitting (alta varianza)

Train acc: muy alta

Val acc: mucho más baja

Memoriza el training. Reduce complejidad (menos profundidad, más datos, regularización).

La curva de aprendizaje muestra el accuracy de train y validación vs el tamaño del training set — revela si hay over/underfitting.

Cómo Comparar Modelos Correctamente

1Usa la misma métrica para todos los modelos (ej. F1-weighted o AUC).
2Usa la misma partición de datos (misma semilla en train_test_split, o el mismo CV).
3Reporta media ± desviación estándar del CV, no solo el accuracy de un fold.
4Considera la diferencia práctica: ¿0.965 vs 0.968 es significativo para tu problema?
5Evalúa también tiempo de entrenamiento y interpretabilidad, no solo el score.
Un modelo más complejo que mejora el accuracy solo un 0.2% pero es 10× más lento puede no valer la pena.
