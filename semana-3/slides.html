El Problema del Árbol Solitario

🎲 Alta varianza

Cambia un par de datos de entrenamiento y el árbol puede cambiar drásticamente. Es inestable.

📉 Propenso a overfitting

Sin controlar max_depth, memoriza el ruido del entrenamiento y falla con datos nuevos.

👁️ Visión limitada

Un solo árbol tiene una "visión" limitada del problema y puede sesgarse por casualidad.

¿Y si en vez de UN árbol usamos 100 árboles que votan juntos?

Semana 3: Random Forest = 100 árboles que votan juntos → más robusto, más preciso, menos overfitting.

La Solución: Aprendizaje de Ensamblado

"Ninguno de nosotros es tan inteligente como todos nosotros juntos." — Kenneth Blanchard

🌳🌳🌳 Bagging (Bootstrap Aggregating)

Entrena múltiples modelos en paralelo, cada uno con una muestra diferente de los datos. Luego combina sus predicciones.

Random Forest usa Bagging.

🔗 Boosting

Entrena modelos en secuencia. Cada nuevo modelo corrige los errores del anterior. Más poderoso pero más lento.

Gradient Boosting, XGBoost usan Boosting.

Ambos son técnicas de ensamblado — combinan modelos débiles para crear uno fuerte.

¿Qué es Random Forest?

Random Forest es un algoritmo de ensamblado que construye múltiples árboles de decisión, cada uno entrenado con una muestra aleatoria de los datos y variables, y combina sus predicciones por votación.

Dos fuentes de aleatoriedad (que dan diversidad a los árboles):

1. Bootstrap de datos — Cada árbol entrena en una muestra diferente (con reemplazo) del dataset original.
2. Aleatoriedad de variables — En cada nodo, solo se consideran √n variables (no todas) para encontrar la mejor división.
La diversidad entre árboles es lo que hace al Random Forest robusto. Si todos los árboles son iguales, votar no ayuda.

Bootstrap Aggregating (Bagging)

Bootstrap = muestreo CON reemplazo. De un dataset de N ejemplos, extraemos N ejemplos al azar (un ejemplo puede aparecer varias veces).

Cada árbol ve una versión diferente del dataset → árboles distintos → errores diferentes → al votar, los errores se cancelan.

~37% de los ejemplos NO aparecen en cada muestra bootstrap. Esos son los datos Out-Of-Bag (OOB) — se usan para validación gratis.

Cómo se Construye un Random Forest

1Elige el número de árboles: n_estimators=100.
2Para cada árbol: extrae una muestra bootstrap del tamaño del training set (con reemplazo).
3Construye un árbol de decisión en esa muestra. En cada nodo, solo considera max_features=√n variables candidatas para la división.
4El árbol crece sin poda (o con max_depth controlado).
5Repite pasos 2–4 para cada uno de los 100 árboles.
6Para predecir: cada árbol vota por una clase. La clase con más votos gana.

Los 100 árboles son independientes entre sí → se pueden construir en paralelo → muy rápido.

Aleatoriedad de Variables (max_features)

En un árbol normal, cada nodo evalúa TODAS las variables para encontrar la mejor división. En Random Forest, solo evalúa una submuestra aleatoria.

Árbol de decisión normal

Dataset con 10 variables. En cada nodo: evalúa las 10 variables. El mejor siempre gana.

→ Todos los árboles tenderán a usar las mismas variables → árboles correlacionados.

Random Forest

Dataset con 10 variables. En cada nodo: evalúa solo √10 ≈ 3 variables elegidas al azar.

→ Árboles usan variables distintas → menos correlacionados → mejor al votar.

Parámetros Clave del Random Forest

n_estimators (default: 100) — Número de árboles. Más árboles = más estable, pero más lento. Raramente vale la pena superar 500.
n_estimators=100 → generalmente suficiente
max_depth (default: None) — Profundidad máxima de cada árbol. En RF se permite crecer profundo porque la votación controla el overfitting.
Puedes dejar None o max_depth=10–20
max_features (default: 'sqrt') — Variables a evaluar en cada nodo. Controla la diversidad entre árboles.
max_features='sqrt' → clasificación
min_samples_split (default: 2) — Igual que en árbol individual. Mínimo de ejemplos para dividir un nodo.
min_samples_split=5 → menos overfitting
oob_score (default: False) — Activar validación con datos Out-Of-Bag. Gratuita, sin necesitar test set.
oob_score=True → valida gratis
n_jobs (default: 1) — Paralelismo. -1 usa todos los procesadores disponibles.
n_jobs=-1 → máxima velocidad

El más importante es n_estimators. Más es mejor, hasta un punto de rendimientos decrecientes (~100–300).

OOB Score — Validación Gratuita

En cada árbol, ~37% de los ejemplos no se usan para entrenamiento (datos Out-Of-Bag). Podemos usar esos ejemplos para validar ese árbol específico.

¿Cómo funciona?

Para cada ejemplo del training set:

1. Identifica qué árboles NO usaron ese ejemplo (sus OOB trees).

2. Hace predicciones solo con esos árboles.

3. Agrega las predicciones por votación.

4. Compara con la etiqueta real.

Ventajas del OOB Score

  • No requiere separar datos para validación
  • Usa TODOS los datos para entrenamiento
  • Estimación imparcial del error real
  • Comparable a cross-validation (Semana 4)
Con oob_score=True, sklearn calcula automáticamente el OOB accuracy sin que hagas nada más.

Importancia de Variables en Random Forest

Igual que en un árbol individual, RF puede decir qué variables fueron más útiles — pero ahora es un promedio sobre 100 árboles, mucho más robusto.

¿Cómo se calcula?

Para cada variable y cada árbol: cuánto redujo el Gini en los nodos donde fue usada. Promedio sobre todos los árboles y normalizado a suma = 1.

rf.feature_importances_

Ventajas vs árbol individual

  • Más estable (promedio de 100 árboles)
  • Menos sesgado hacia variables con más categorías
  • Detecta variables que solo ayudan en combinación

La importancia de variables es una de las razones por las que RF es muy usado en la industria — es un modelo interpretable y robusto.

Introducción al Gradient Boosting

Random Forest construye árboles en paralelo. Gradient Boosting los construye en secuencia — cada árbol corrige los errores del anterior.

Random Forest — Paralelo

Árbol 1 Árbol 2 Árbol 3 → votan

Cada árbol aprende de datos diferentes (bootstrap). Son independientes.

Gradient Boosting — Secuencial

Árbol 1 → errores → Árbol 2 → errores → Árbol 3 → suma

Cada árbol aprende de los errores del anterior. Los árboles son pequeños (stumps).

Gradient Boosting es más poderoso pero más propenso a overfitting y más lento. Se profundiza en Semana 4.
