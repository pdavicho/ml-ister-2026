Motivación

¿Por qué SVM?

El problema de los árboles

  • Los árboles de decisión crean fronteras rectangulares
  • Son sensibles a pequeños cambios en los datos
  • Con datos ruidosos pueden sobreajustarse fácilmente

La propuesta SVM

  • Encuentra la frontera que maximiza la separación entre clases
  • Sólido fundamento matemático (optimización convexa)
  • Funciona bien en espacios de alta dimensión
SVM no busca solo cualquier frontera de decisión — busca la mejor posible: la que está más lejos de todos los puntos.
Concepto clave

Separabilidad Lineal

Dados puntos de dos clases en el plano, existen infinitos hiperplanos que los separan correctamente.

Pregunta: ¿Cuál de todos esos hiperplanos es el mejor?
SVM elige el hiperplano que maximiza el margen entre las dos clases

Definición: Hiperplano

En 2D: una recta. En 3D: un plano. En N dimensiones: un hiperplano.

Ecuación general:

w · x + b = 0

Donde w es el vector normal al hiperplano y b es el sesgo.

Margen

Distancia entre el hiperplano y el punto más cercano de cada clase.

margen = 2 / ‖w‖

Objetivo SVM

Maximizar el margen equivale a minimizar ‖w‖² sujeto a que todos los puntos estén correctamente clasificados.

Robustez

Mayor margen → menor error de generalización → mejor rendimiento en datos nuevos.

Pieza fundamental

Vectores de Soporte

Los vectores de soporte son los puntos de entrenamiento que están más cerca del hiperplano — están sobre los bordes del margen.

Dato crucial: solo los vectores de soporte determinan el hiperplano. El resto de los puntos no importan.
Consecuencia práctica: Si eliminamos puntos que no son vectores de soporte, el hiperplano no cambia.

¿Por qué "vectores"?

Porque matemáticamente son vectores en el espacio de características que "sostienen" (support) el margen.

Condición matemática

Para los vectores de soporte se cumple:

y_i (w · x_i + b) = 1

Para el resto de puntos: ≥ 1

Parámetro C

SVM Duro vs SVM Blando

⚔️ Margen Duro (Hard Margin)

  • No permite ningún punto dentro del margen
  • Solo funciona si los datos son perfectamente separables
  • Muy sensible a datos atípicos (outliers)
Rara vez aplicable en datos reales

🛡️ Margen Blando (Soft Margin)

  • Permite algunos puntos dentro del margen o mal clasificados
  • Controlado por el parámetro C
  • Balance entre margen ancho y errores de clasificación
El SVM real que usamos en práctica
C pequeño (ej. 0.01): margen más ancho, más errores permitidos → mayor generalización, posible underfitting
C grande (ej. 100): margen más estrecho, menos errores → más ajuste a los datos, posible overfitting
El gran salto

Datos No Linealmente Separables

¿Qué pasa cuando los datos no se pueden separar con una línea recta? (Ej: puntos en círculos concéntricos)

Idea clave: Si proyectamos los datos a un espacio de mayor dimensión, puede que sí sean separables linealmente.
Proyectar a dimensiones muy altas puede ser muy costoso computacionalmente.

Ejemplo intuitivo

Puntos en 1D: {1, 2, 3, 4, 5} con clases {−, −, +, −, −}

No son separables con un punto.

Proyectar a 2D: (x, x²)

Ahora los "+" están arriba y los "−" abajo → ¡separables linealmente!

El Kernel Trick hace esto eficientemente
La magia de SVM

El Kernel Trick

Un kernel es una función K(x, y) que calcula el producto punto en un espacio de alta dimensión sin necesidad de calcular la proyección explícita.

Sin kernel

1. Proyectar todos los puntos a ℝⁿ

2. Calcular producto punto en ℝⁿ

Costo: O(n²) — muy caro

Con kernel

1. Calcular K(x_i, x_j) directamente en el espacio original

Costo: O(1) — tan simple como una función

Por qué funciona

El teorema de Mercer garantiza que ciertas funciones K(x,y) corresponden a un producto punto en algún espacio de Hilbert.

El algoritmo SVM solo necesita el resultado de K(x_i, x_j) — nunca necesita ver la proyección φ(x)
Opciones de kernel

Kernels más usados

KernelFórmulaParámetrosCuándo usar
Lineal K(x,y) = x · y — Datos linealmente separables, muchas características (texto, genómica)
RBF / Gaussiano K(x,y) = exp(−γ‖x−y‖²) γ (gamma) Fronteras no lineales. El más usado en la práctica.
Polinomial K(x,y) = (γ·x·y + r)ᵈ d (grado), γ, r Datos con interacciones polinomiales (visión, NLP)
Sigmoide K(x,y) = tanh(γ·x·y + r) γ, r Similar a red neuronal de 2 capas. Poco usado.
Regla práctica: empieza siempre con kernel RBF y ajusta C y γ con validación cruzada.
RBF Kernel

El Parámetro Gamma (γ)

γ controla la influencia de cada punto de entrenamiento en la frontera de decisión.

K(x,y) = exp(−γ‖x−y‖²)
  • γ pequeño: función amplia → puntos lejanos también influyen → frontera suave → underfitting posible
  • γ grande: función estrecha → solo puntos muy cercanos influyen → frontera irregular → overfitting posible

Relación C ↔ γ

C y γ se controlan juntos:

CγResultado
pequeñopequeñoMuy suave, underfitting
grandegrandeMuy complejo, overfitting
mediomedioBalance óptimo
Usar GridSearchCV para encontrar los mejores valores
Más de 2 clases

SVM para Clasificación Multiclase

SVM es un clasificador binario por naturaleza. Para multiclase se usan dos estrategias:

OvO — One vs One

Para K clases: entrena K(K−1)/2 clasificadores, uno por cada par de clases.

Ejemplo (K=3): Clase1 vs Clase2 · Clase1 vs Clase3 · Clase2 vs Clase3

Predicción: clase con más "votos" gana.

Por defecto en scikit-learn

OvR — One vs Rest

Para K clases: entrena K clasificadores, cada uno distingue una clase de todas las demás.

Ejemplo (K=3): Clase1 vs {2,3} · Clase2 vs {1,3} · Clase3 vs {1,2}

Predicción: clase con mayor puntuación de confianza.

Puede haber desbalance en las clases
Scikit-learn: usa OvO por defecto en SVC. Para OvR usar LinearSVC o SVC con decision_function_shape='ovr'
Preprocesamiento crítico

Normalización: Obligatoria en SVM

SVM calcula distancias entre puntos. Si las características tienen escalas muy distintas, las de mayor escala dominarán el cálculo del margen.

SVM sin normalizar → resultados poco confiables o muy malos
SVM con StandardScaler → comportamiento correcto y estable

StandardScaler

Transforma cada característica para tener media=0 y std=1:

x' = (x − μ) / σ

Regla de oro: ajustar el scaler SOLO en los datos de entrenamiento, aplicarlo en test.

scaler.fit(X_train)
scaler.transform(X_train)
scaler.transform(X_test) ← no fit aquí

Análisis crítico

SVM — Ventajas y Desventajas

✅ Ventajas

  • Muy efectivo en espacios de alta dimensión
  • Funciona bien cuando hay más características que muestras
  • Usa solo los vectores de soporte → eficiente en memoria
  • Versátil: diferentes kernels para diferentes problemas
  • Sólida base teórica (optimización convexa → único mínimo global)

❌ Desventajas

  • Lento en datasets muy grandes (O(n²) a O(n³) en entrenamiento)
  • Sensible a la elección de kernel y parámetros C, γ
  • No produce probabilidades directamente (requiere calibración)
  • Difícil de interpretar: ¿qué aprendió el modelo?
  • Requiere normalización obligatoria
SVM es ideal para: datasets medianos (≤ 10,000 muestras) con pocas clases y características relevantes. Para millones de datos, considera SGD o árboles.

Resumen práctico

Flujo de Trabajo con SVM

1Preprocesar: normalizar con StandardScaler (fit solo en train)
2Elegir kernel: empezar con RBF, probar lineal si hay muchas características
3Ajustar hiperparámetros: GridSearchCV sobre C y γ con cross-validation
4Evaluar: accuracy, F1, curva ROC — ojo con clases desbalanceadas
5Comparar: SVM vs Random Forest en tus datos específicos
No existe el "mejor algoritmo universal". SVM sobresale cuando los datos tienen estructura bien definida y son de tamaño medio.
